The search for "HTML5 anchor download filename sanitization Windows reserved characters vanilla JS" returned the following summary:
When building client-side file downloads using vanilla JavaScript and the HTML5 `download` attribute (`<a href="..." download="filename">`), user-provided or dynamically generated strings can easily break downloads or cause security issues on Windows machines[1][2]. 

Windows file systems disallow specific **reserved characters**, **control codes**, **device names** (like `CON`, `NUL`, `COM1`), and **trailing periods/spaces**[3][4][5].

Here is a robust, production-ready vanilla JavaScript helper function to thoroughly sanitize filenames for cross-platform safety (with a heavy focus on Windows limitations):

### Vanilla JS Sanitization Function

```javascript
function sanitizeFilename(input, replacement = '_') {
  if (typeof input !== 'string') return 'download';

  // 1. Control characters (0x00–0x1f and 0x80–0x9f)
  const controlRe = /[\x00-\x1f\x80-\x9f]/g;
  
  // 2. Windows reserved characters: < > : " / \ | ? *
  const reservedCharsRe = /[<>:"/\\|?*]/g;
  
  // 3. Windows reserved device names (CON, PRN, AUX, NUL, COM1-9, LPT1-9) with optional extension
  const windowsReservedRe = /^(con|prn|aux|nul|com[1-9]|lpt[1-9])(\..*)?$/i;
  
  // 4. Unix hidden files or relative paths if stripped poorly (optional safeguard for just dots)
  const leadingTrailingDotsSpacesRe = /^[. ]+|[. ]+$/g;

  let sanitized = input
    .replace(controlRe, replacement)
    .replace(reservedCharsRe, replacement)
    .trim();

  // Handle Windows reserved device names by prefixing them if matched
  if (windowsReservedRe.test(sanitized)) {
    sanitized = replacement + sanitized;
  }

  // Strip leading/trailing dots and spaces (Windows drops/malfunctions with these)
  sanitized = sanitized.replace(leadingTrailingDotsSpacesRe, '');

  // Fallback if string became completely empty
  if (!sanitized || sanitized === '') {
    sanitized = 'download';
  }

  // Truncate to safe byte/character length (Windows max filename length is typically 255 chars)
  return sanitized.slice(0, 255);
}
```

### How to use it with an HTML5 Anchor Tag (`<a>`)

You can combine this function with a Blob or a local data/object URL to trigger a safe, programmatic download in vanilla JavaScript:

```javascript
function triggerDownload(userProvidedName, fileContent, mimeType = 'text/plain') {
  // 1. Sanitize the filename
  const safeName = sanitizeFilename(userProvidedName);

  // 2. Create a Blob from the content
  const blob = new Blob([fileContent], { type: mimeType });
  const blobUrl = URL.createObjectURL(blob);

  // 3. Create dynamic anchor element
  const anchor = document.createElement('a');
  anchor.href = blobUrl;
  anchor.download = safeName; // HTML5 download attribute

  // 4. Append to DOM, click to fire download, then clean up
  document.body.appendChild(anchor);
  anchor.click();
  
  document.body.removeChild(anchor);
  URL.revokeObjectURL(blobUrl);
}

// --- Example Usage ---
// This will clean out invalid characters like '?', ':', and spaces, 
// and safely handle the Windows reserved word "CON".
triggerDownload('CON?report:2026.txt', 'Here is the report data.');
// Resulting downloaded file: "_CON_report_2026.txt"
```

### Key Rules Handled by This Sanitizer:
1. **Windows Restricted Symbols:** Strips out `<`, `>`, `:`, `"`, `/`, `\`, `|`, `?`, and `*`[3][5][6].
2. **ASCII Control Codes:** Removes invisible or layout-breaking control characters (`0x00` to `0x1F`)[3][4].
3. **Windows Reserved Words:** Detects names like `CON`, `NUL`, `AUX`, `COM1`, etc. (case-insensitive) and prefixes them so Windows doesn't reject the file write[3][4].
4. **Trailing/Leading Spaces & Periods:** Prevents file creation glitches on NTFS formatting by stripping edge spaces and dots (`.`)[4][5].
5. **Length Restriction:** Caps the filename at 255 characters to abide by standard OS file system limits[3][4].
