The search for "web accessibility empty state notice hide action buttons unavailable feature vanilla HTML CSS" returned the following summary:
When designing an **Empty State** notice that needs to completely hide action buttons due to an unavailable feature, relying strictly on visual CSS (`display: none`) is often enough for a simple removal. However, to build a truly accessible experience using vanilla HTML and CSS, you must ensure that state changes are handled cleanly so that screen readers and keyboard users aren't left with orphaned interactions or confusing layouts[1][2].

Here is the best-practice approach using **Vanilla HTML and CSS**:

### 1. The HTML Structure
Keep the container semantic. If the entire action panel or button group needs to disappear conditionally based on feature availability, wrap it in a structural element or target the buttons directly. 

```html
<section class="empty-state" aria-labelledby="empty-title">
  <div class="empty-state__icon" aria-hidden="true">📁</div>
  <h2 id="empty-title" class="empty-state__title">No Projects Found</h2>
  <p class="empty-state__description">You haven't created any projects yet. Get started by creating your first one.</p>
  
  <!-- Action button container -->
  <div class="empty-state__actions" id="action-buttons-group">
    <!-- Feature available: Button shows -->
    <button type="button" class="btn btn-primary">Create Project</button>
    
    <!-- Feature UNAVAILABLE: Handled via CSS or conditional rendering -->
    <button type="button" class="btn btn-secondary feature-unavailable">Import from Template</button>
  </div>
</section>
```

---

### 2. The CSS Solution (Hiding Unavailable Features)
If a specific feature is permanently or temporarily unavailable and you want to **completely hide** its action button while keeping the empty state clean, use standard layout hiding[3][4]. 

Using `display: none` removes the element visually, layout-wise, and **completely removes it from the accessibility tree** (screen readers will ignore it, and keyboard users cannot tab to it)[3].

```css
/* Base Empty State Styling */
.empty-state {
  display: flex;
  flex-direction: column;
  align-items: center;
  text-align: center;
  padding: 3rem 1.5rem;
  max-width: 400px;
  margin: 0 auto;
}

.empty-state__title {
  font-size: 1.25rem;
  font-weight: 600;
  margin: 1rem 0 0.5rem;
}

.empty-state__description {
  color: #6b7280;
  font-size: 0.95rem;
  margin-bottom: 1.5rem;
}

.empty-state__actions {
  display: flex;
  gap: 0.75rem;
  flex-wrap: wrap;
  justify-content: center;
}

/* --- HIDING UNAVAILABLE FEATURES --- */

/* Approach A: Hide a single unavailable feature button */
.btn.feature-unavailable {
  display: none; 
}

/* Approach B: If ALL actions are unavailable, hide the whole wrapper */
.empty-state__actions.all-features-unavailable {
  display: none;
}
```

---

### Alternative: What if you shouldn't hide it, but rather make it explicitly clear it's unavailable?
Accessibility experts often advise against completely hiding interactive elements if users expect them to be there (as it can cause confusion). Instead of hiding, an accessible pattern is to use the native HTML **`inert`** attribute combined with text communication[1][2]:

```html
<!-- The inert attribute makes the button unfocusable, unclickable, and strips it from screen readers natively -->
<button type="button" class="btn btn-secondary" inert aria-describedby="feature-notice">
  Import from Template
</button>
<p id="feature-notice" class="sr-only">This feature is temporarily unavailable.</p>
```
*Note: If supporting older browsers that don't recognize `inert`[5], you would toggle `tabindex="-1"`, `aria-disabled="true"`, and pointer-events via CSS, though modern browsers universally support `inert`.*

### Summary Checklist for Vanilla Implementation:
1. **To completely remove the unavailable feature:** Use `display: none;` on the button or its wrapper. This natively resolves accessibility because hidden elements cannot be focused or read[3][4].
2. **Never use `aria-hidden="true"` alone on a button:** If you hide something with ARIA alone while leaving it focusable, it creates a severe "keyboard trap" where screen reader users can tab into an invisible, silent element[1]. Stick to `display: none` or `inert`[1].
