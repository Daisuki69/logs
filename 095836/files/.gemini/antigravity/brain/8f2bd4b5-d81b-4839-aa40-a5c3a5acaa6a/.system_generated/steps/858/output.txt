The search for "firestore rest api value types mapValue arrayValue integerValue stringValue booleanValue" returned the following summary:
In the **Cloud Firestore REST API**, every document field value is wrapped in a type-safe object called a **`Value`**[1]. Because the REST API uses explicit typing instead of standard JSON type inference, you must specify the exact data type wrapper for every field (e.g., `stringValue`, `integerValue`, `booleanValue`, `mapValue`, `arrayValue`)[2][3].

Below is an overview and JSON payload example demonstrating how to use these specific value types in Firestore REST API requests (`POST` or `PATCH`)[4][3].

---

### 1. `stringValue`
* **Description:** Represents a UTF-8 text string[1].
* **JSON Syntax:** `"stringValue": "your_string_here"`[3]

### 2. `integerValue`
* **Description:** Represents a 64-bit integer (`int64`)[1]. 
* **Important:** In the REST API, integer values must be passed as **strings** (e.g., `"123"`) to prevent precision loss in languages/environments that handle JSON numbers as standard floating-point types[1].
* **JSON Syntax:** `"integerValue": "42"` (or sometimes accepted as a raw number depending on the client library, but strictly specified as a string `string (int64 format)` in the official protocol reference)[1].

### 3. `booleanValue`
* **Description:** Represents a boolean (`true` or `false`)[1].
* **JSON Syntax:** `"booleanValue": true`

### 4. `mapValue`
* **Description:** Represents a nested object or map containing its own set of fields[5]. It wraps a nested `fields` object[5][4].
* **JSON Syntax:** 
  ```json
  "mapValue": {
    "fields": {
      "nestedFieldKey": { "stringValue": "nested value" }
    }
  }
  ```

### 5. `arrayValue`
* **Description:** Represents an ordered list/array of Firestore `Value` items[1]. It wraps an array called `values`[1].
* **JSON Syntax:** 
  ```json
  "arrayValue": {
    "values": [
      { "stringValue": "item1" },
      { "integerValue": "10" }
    ]
  }
  ```

---

### Complete Example Payload

Here is how you combine all of these types together into a standard Firestore REST API document body (e.g., when creating or updating a document)[3]:

```json
{
  "fields": {
    "username": {
      "stringValue": "johndoe"
    },
    "age": {
      "integerValue": "30"
    },
    "isActive": {
      "booleanValue": true
    },
    "tags": {
      "arrayValue": {
        "values": [
          { "stringValue": "admin" },
          { "stringValue": "developer" }
        ]
      }
    },
    "address": {
      "mapValue": {
        "fields": {
          "city": { "stringValue": "New York" },
          "zipCode": { "integerValue": "10001" }
        }
      }
    }
  }
}
```
