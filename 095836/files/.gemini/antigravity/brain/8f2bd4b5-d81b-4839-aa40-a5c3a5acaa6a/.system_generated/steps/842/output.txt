The search for "firestore rest api cors origin null file protocol fetch json" returned the following summary:
Running a JavaScript `fetch()` request to the **Firestore REST API** from a web page loaded via the `file://` protocol will typically cause a CORS (Cross-Origin Resource Sharing) error, reporting an origin of **`null`**[1][2].

This happens because of two overlapping security constraints built into modern web browsers:

1. **The `file://` Protocol Origin is `null`:** When you open an HTML file directly from your local file system (`file:///path/to/index.html`), browsers assign it an `Origin: null` security header because local files do not belong to a standard web domain or scheme.
2. **CORS and `null` Origins:** When a script running on an `origin: null` makes a `fetch()` call to an external REST API like `https://firestore.googleapis.com/...`, the browser blocks the response if the server's CORS headers don't explicitly allow `Origin: null`. Google’s public APIs do not return `Access-Control-Allow-Origin: null` for security reasons.

---

### How to Fix It

#### Solution 1: Run a Local Development Server (Recommended)
The correct way to develop web apps that use `fetch()` is to serve your frontend files through a local HTTP server (`http://localhost:...` or `http://127.0.0.1:...`) rather than opening them directly as files[2]. This changes your origin from `null` to a valid localhost origin.

You can spin up a local server instantly using tools you likely already have installed:

* **Node.js (npx):**
  ```bash
  npx http-server .
  ```
* **Python (3.x):**
  ```bash
  python3 -m http.server 8000
  ```
* **VS Code:** Install the **Live Server** extension and click "Go Live" at the bottom right.

Once your app runs on `http://localhost:8000`, browsers will send `Origin: http://localhost:8000`. (Note: Firestore REST API handles standard web origins correctly out of the box for most standard browser interactions, or you can route through the Firebase JS SDK which manages transport layers cleanly).

---

#### Solution 2: Use a Backend Proxy (If stuck on `file://` or custom local setups)
If your architecture strictly requires executing code in an environment mapped to `file://` where you cannot change the origin, client-side `fetch()` directly to Google APIs will always fail due to browser security restrictions. 

Instead, route your `fetch` request through a local backend proxy (like a small Express.js app)[3]:
1. Your frontend (`file://` or local script) fetches from `http://localhost:3000/api/firestore`.
2. Your Node.js backend receives the request, queries `https://firestore.googleapis.com/...` server-side (server-to-server requests **do not** enforce CORS restrictions), and returns the JSON payload back to your client.
