The search for "master detail web UI back button vs top nav tab navigation URL history replaceState vanilla JS" returned the following summary:
When designing a **Master-Detail web UI** with tab navigation using vanilla JavaScript, managing the browser's history correctly is vital[1]. A common UX bug is "back-button hijacking"—where clicking through tabs or detail views forces the user to press the back button dozens of times just to leave the page[2].

The core architectural choice comes down to knowing when to use **`history.pushState()`** versus **`history.replaceState()`**[3].

---

### 1. The Core Rules: `pushState` vs `replaceState`

*   **`pushState()` (Create a new history entry):** Use this when the user navigates to a **genuinely new context or drill-down** (e.g., clicking a Master item to open the Detail view). The user expects the browser’s Back button to return them to the previous master state[3].
*   **`replaceState()` (Modify the current history entry):** Use this when switching **tabs, filters, or sub-views *within* the same context** (e.g., switching from the "Overview" tab to the "Settings" tab inside a Detail view)[3]. This keeps the URL updated for bookmarking/sharing without cluttering the browser's history stack with redundant steps[4][3][1].

---

### 2. Recommended Navigation Flow Pattern

1.  **List to Detail (Master Click):** Use **`pushState`**. 
    *   *Why:* Going from a list of 20 items to inspecting Item A is a structural navigation step. Back should close/leave the detail view.
2.  **Tab Switching inside Detail:** Use **`replaceState`**.
    *   *Why:* If a user clicks "Overview" $\rightarrow$ "Activity" $\rightarrow$ "Settings" inside Item A's detail page, clicking "Back" should take them *back to the Master list*, not cycle backward through Item A's tabs[3].

---

### 3. Vanilla JavaScript Implementation Blueprint

Here is how you wire up a master-detail interface using vanilla JavaScript, URL manipulation, and the `popstate` event[4][1]:

#### HTML Structure Skeleton
```html
<!-- Master View -->
<div id="master-view">
  <ul>
    <li><a href="#" class="item-link" data-id="1">Item 1</a></li>
    <li><a href="#" class="item-link" data-id="2">Item 2</a></li>
  </ul>
</div>

<!-- Detail View (Hidden by default) -->
<div id="detail-view" style="display: none;">
  <button id="back-to-master">← Back to List</button>
  
  <!-- Top Nav Tabs -->
  <nav class="tabs">
    <button class="tab-btn" data-tab="overview">Overview</button>
    <button class="tab-btn" data-tab="activity">Activity</button>
  </nav>

  <div id="tab-content"></div>
</div>
```

#### Vanilla JS Router & State Manager
```javascript
const masterView = document.getElementById('master-view');
const detailView = document.getElementById('detail-view');
const tabContent = document.getElementById('tab-content');

// 1. Handle Master Item Click (PUSH state)
document.querySelectorAll('.item-link').forEach(link => {
  link.addEventListener('click', (e) => {
    e.preventDefault();
    const itemId = e.target.getAttribute('data-id');
    
    // Push a new history entry because we are entering a detail context
    const url = `/item/${itemId}?tab=overview`;
    history.pushState({ itemId, tab: 'overview' }, '', url);
    
    renderDetail(itemId, 'overview');
  });
});

// 2. Handle Tab Navigation Inside Detail (REPLACE state)
document.querySelectorAll('.tab-btn').forEach(btn => {
  btn.addEventListener('click', (e) => {
    const tabName = e.target.getAttribute('data-tab');
    const urlParams = new URLSearchParams(window.location.search);
    const itemId = urlParams.get('item') || getCurrentItemId(); // or extract from path

    // Replace current state so tab changes don't spam the back-button stack
    const url = `/item/${itemId}?tab=${tabName}`;
    history.replaceState({ itemId, tab: tabName }, '', url);
    
    renderTabContent(tabName);
  });
});

// 3. Handle Browser Back/Forward Buttons
window.addEventListener('popstate', (event) => {
  const state = event.state;

  if (!state || !state.itemId) {
    // User went back to the root Master view
    masterView.style.display = 'block';
    detailView.style.display = 'none';
  } else {
    // User navigated through history states inside details
    masterView.style.display = 'none';
    detailView.style.display = 'block';
    renderDetail(state.itemId, state.tab);
  }
});

// 4. Helper rendering functions
function renderDetail(itemId, tab) {
  masterView.style.display = 'none';
  detailView.style.display = 'block';
  // Fetch or populate data for itemId...
  renderTabContent(tab);
}

function renderTabContent(tabName) {
  document.querySelectorAll('.tab-btn').forEach(b => b.classList.remove('active'));
  document.querySelector(`[data-tab="${tabName}"]`)?.classList.add('active');
  tabContent.innerHTML = `<p>Loading content for ${tabName}...</p>`;
}

// Optional: Handle initial page load matching current URL
window.addEventListener('DOMContentLoaded', () => {
  const pathParts = window.location.pathname.split('/');
  const itemId = pathParts[2]; // assuming /item/:id structure
  const params = new URLSearchParams(window.location.search);
  const tab = params.get('tab') || 'overview';

  if (itemId) {
    renderDetail(itemId, tab);
  }
});
```

### Summary Checklist for Best UX

| Action Performed by User | History Method to Use | Expected Back Button Behavior |
| :--- | :--- | :--- |
| **Master $\rightarrow$ Detail** | `history.pushState()`[3] | Returns user back to the master list[3]. |
| **Switching Tabs (Overview $\leftrightarrow$ Settings)** | `history.replaceState()`[3] | Skips intermediate tabs and returns user directly to the master list[3]. |
| **Applying Filters / Search Queries** | `history.replaceState()`[3] | Updates URL for link sharing, but pressing back exits the filtered view instead of undoing every keystroke/filter toggle[3][2]. |
