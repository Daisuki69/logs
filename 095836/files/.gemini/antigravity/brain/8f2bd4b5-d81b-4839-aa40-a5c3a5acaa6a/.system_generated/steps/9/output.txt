The search for "firebase 10 firestore modular cdn gstatic unpkg" returned the following summary:
To use the **Firebase 10+ Modular Web SDK** directly via a CDN (without using a build tool like Webpack, Vite, or npm), you should use **Google's official `gstatic` CDN** with native browser ES modules (`type="module"`). 

While networks like **UNPKG** or **jsDelivr** host Firebase packages[1], Firebase officially recommends and hosts the bundled browser-ready modular ES modules directly on `gstatic`[2].

### 1. Using Google's Official `gstatic` CDN (Recommended for Vanilla JS)

Here is how to set up Firebase 10 Firestore using native ES module imports in your HTML file:

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Firebase 10 Firestore CDN Example</title>
</head>
<body>

    <h1>My Firebase 10 App</h1>

    <script type="module">
        // Import the functions you need from the SDKs on the gstatic CDN
        import { initializeApp } from "https://www.gstatic.com/firebasejs/10.14.0/firebase-app.js";
        import { getFirestore, collection, addDoc, getDocs } from "https://www.gstatic.com/firebasejs/10.14.0/firebase-firestore.js";

        // Your web app's Firebase configuration
        const firebaseConfig = {
            apiKey: "YOUR_API_KEY",
            authDomain: "YOUR_PROJECT_ID.firebaseapp.com",
            projectId: "YOUR_PROJECT_ID",
            storageBucket: "YOUR_PROJECT_ID.appspot.com",
            messagingSenderId: "YOUR_SENDER_ID",
            appId: "YOUR_APP_ID"
        };

        // Initialize Firebase
        const app = initializeApp(firebaseConfig);

        // Initialize Cloud Firestore and get a reference to the service
        const db = getFirestore(app);

        // Example: Writing data to Firestore
        async function writeData() {
            try {
                const docRef = await addDoc(collection(db, "users"), {
                    first: "Ada",
                    last: "Lovelace",
                    born: 1815
                });
                console.log("Document written with ID: ", docRef.id);
            } catch (e) {
                console.error("Error adding document: ", e);
            }
        }

        // Example: Reading data from Firestore
        async function readData() {
            const querySnapshot = await getDocs(collection(db, "users"));
            querySnapshot.forEach((doc) => {
                console.log(`${doc.id} =>`, doc.data());
            });
        }

        writeData();
        readData();
    </script>
</body>
</html>
```

### 2. Using UNPKG or jsDelivr (Alternative CDN)

If your environment specifically requires **UNPKG** or **jsDelivr**, you must target the specific modular npm packages (`@firebase/app` and `@firebase/firestore`). Because these npm packages rely on internal dependencies, pointing straight to them via browser ESM requires proper path resolution. 

Using **esm.sh** or **jsDelivr** with `esm` support handles these dependencies automatically:

```html
<script type="module">
    // Using jsDelivr's ESM endpoint which automatically resolves internal package dependencies
    import { initializeApp } from "https://cdn.jsdelivr.net/npm/firebase@10.14.0/+esm";
    import { getFirestore, collection, getDocs } from "https://cdn.jsdelivr.net/npm/@firebase/firestore@10.14.0/+esm";

    // Configuration and initialization logic goes here...
</script>
```

### Key Rules to Remember:
1. **`type="module"` is mandatory:** Browser ES module imports (`import ... from "..."`) only work inside script tags explicitly marked with `type="module"`[3].
2. **Version matching:** Always ensure that all Firebase service imports (`firebase-app.js`, `firebase-firestore.js`, etc.) share the **exact same version number** (e.g., `10.14.0`) to avoid mismatched internal dependency errors.
