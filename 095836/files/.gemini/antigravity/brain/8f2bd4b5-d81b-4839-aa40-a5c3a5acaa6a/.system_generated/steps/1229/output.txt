The search for "destructive confirmation dialog combined action UX clear records and reset state vanilla HTML JS" returned the following summary:
When dealing with high-stakes destructive actions—such as **clearing records AND resetting the application state** entirely—a standard "Are you sure?" modal is often insufficient. Best-practice UX design for combined, irreversible actions relies on introducing intentional friction[1]:
1. **Explicit Consequence Disclosure:** Clearly state *everything* that will be wiped out[2][3].
2. **Type-to-Confirm Mechanism:** Force the user to type a specific validation keyword (e.g., `RESET` or `DELETE`) to unlock the destructive button[3]. This stops accidental click-throughs.
3. **Visual Danger Stacking:** Use high-contrast destructive cues (red accents, warning icons)[1][4].

Below is a complete, production-ready implementation using **Vanilla HTML, CSS, and JavaScript**.

### 3. Application Logic (`script.js`)
```javascript
document.addEventListener('DOMContentLoaded', () => {
    const openBtn = document.getElementById('open-modal-btn');
    const modal = document.getElementById('destructive-modal');
    const cancelBtn = document.getElementById('modal-cancel-btn');
    const confirmBtn = document.getElementById('modal-confirm-btn');
    const confirmInput = document.getElementById('confirmation-input');
    
    // UI elements to mutate on reset
    const recordCountEl = document.getElementById('record-count');
    const appModeEl = document.getElementById('app-mode');
    const toast = document.getElementById('toast');

    // 1. Open Modal & Setup Focus Trap / Initial State
    function openModal() {
        modal.classList.remove('hidden');
        modal.setAttribute('aria-hidden', 'false');
        confirmInput.value = '';
        confirmBtn.disabled = true;
        confirmInput.focus();
    }

    // 2. Close Modal Safely
    function closeModal() {
        modal.classList.add('hidden');
        modal.setAttribute('aria-hidden', 'true');
        openBtn.focus();
    }

    // 3. Friction Logic: Enforce exact keyword string match ("RESET")
    confirmInput.addEventListener('input', (e) => {
        const targetValue = e.target.value.trim();
        if (targetValue === 'RESET') {
            confirmBtn.disabled = false;
        } else {
            confirmBtn.disabled = true;
        }
    });

    // 4. Combined Action Execution (Clear Records + Reset State)
    function executeDestructiveAction() {
        // Perform Mock Operations
        recordCountEl.textContent = '0';
        appModeEl.textContent = 'Factory Reset State';
        appModeEl.style.backgroundColor = '#fee2e2';
        appModeEl.style.color = '#991b1b';

        closeModal();
        showToast();
    }

    // 5. Success Toast Feedback
    function showToast() {
        toast.classList.remove('hidden');
        setTimeout(() => {
            toast.classList.add('hidden');
        }, 3500);
    }

    // Event Listeners
    openBtn.addEventListener('click', openModal);
    cancelBtn.addEventListener('click', closeModal);
    confirmBtn.addEventListener('click', executeDestructiveAction);

    // Dismiss modal on backdrop click or Escape key
    modal.addEventListener('click', (e) => {
        if (e.target === modal) closeModal();
    });

    window.addEventListener('keydown', (e) => {
        if (e.key === 'Escape' && !modal.classList.contains('hidden')) {
            closeModal();
        }
    });
});
```

### Why this works well for UX:
* **The "No-Brainer" Exit:** The secondary action button is explicitly labeled **Cancel** and sits cleanly away from the dangerous trigger path[3].
* **Cognitive Speed Bump:** Requiring the user to type `RESET` forces them to break autopilot, ensuring they actually read the danger notice[3][1].
* **State Mutation Feedback:** Immediately updates the dashboard metrics and flashes a confirmation toast so the user has visual validation that the complex action completed successfully.
